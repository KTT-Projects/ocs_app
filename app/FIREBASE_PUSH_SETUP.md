# Firebase push setup

The app now registers FCM tokens with the backend when a logged-in user enables device alerts.

## Firebase files

Firebase apps have been created in the `shineportal-ktt` project for:

- Web: `Kami Lander Web`
- Android: `com.kttprojects.kamiLander`
- iOS: `com.kttprojects.kamiLander`

Native Firebase config files are already present at:

- `android/app/google-services.json`
- `ios/Runner/GoogleService-Info.plist`

The checked-in `lib/services/firebase_options.dart` also includes the matching Firebase defaults and the generated Web Push VAPID public key. You only need `--dart-define` overrides if you intentionally move this app to a different Firebase project.

## Required build values

For web builds, these values are already configured by default:

```sh
FIREBASE_PROJECT_ID=shineportal-ktt
FIREBASE_MESSAGING_SENDER_ID=299843107216
FIREBASE_WEB_APP_ID=1:299843107216:web:e06d18c6e193209491db15
FIREBASE_WEB_AUTH_DOMAIN=shineportal-ktt.firebaseapp.com
FIREBASE_WEB_STORAGE_BUCKET=shineportal-ktt.appspot.com
FIREBASE_WEB_MEASUREMENT_ID=G-6YRL4BN758
```

`web/firebase-messaging-sw.js` contains the same Firebase web app config because service workers cannot read Dart defines at runtime.

For Android/iOS, either add the Firebase platform files generated by FlutterFire or pass:

```sh
--dart-define=FIREBASE_PROJECT_ID=...
--dart-define=FIREBASE_MESSAGING_SENDER_ID=...
--dart-define=FIREBASE_ANDROID_API_KEY=...
--dart-define=FIREBASE_ANDROID_APP_ID=...
--dart-define=FIREBASE_IOS_API_KEY=...
--dart-define=FIREBASE_IOS_APP_ID=...
--dart-define=FIREBASE_IOS_BUNDLE_ID=com.kttprojects.kamiLander
```

## iOS

The project includes `Runner.entitlements` and `UIBackgroundModes` for push notifications. In Xcode, confirm the Runner target has:

- Push Notifications capability.
- Background Modes capability with Background fetch and Remote notifications.

For release builds, change `aps-environment` in `ios/Runner/Runner.entitlements` from `development` to `production` if Xcode does not manage it automatically.

## Backend registration

After Firebase initializes, the app posts FCM tokens to:

```text
POST https://ocs.kttprojects.com/api/push_notifications.php?action=register
```

On logout, it calls:

```text
POST https://ocs.kttprojects.com/api/push_notifications.php?action=unregister
```
